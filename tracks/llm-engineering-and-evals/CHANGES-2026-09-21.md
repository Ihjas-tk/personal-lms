# Required, optional and either/or resources — track.yaml review, 2026-09-21

Package B of `docs/superpowers/plans/2026-09-21-required-optional-resources-plan.md`. Every one of
the 20 modules was read against [`README.md`](README.md) (the syllabus prose) and
[`research/05`, `06`, `08`](research/). Four new resource fields are used:

- `required: false` — an extra the syllabus calls optional, a companion, or a second source that
  duplicates a primary. Never blocks a topic.
- `alternative_of` + `lane` — an explicit "either / or" in the syllabus, expressed as a group that
  is satisfied by any one member.
- `focus` — one line saying which part of a resource this topic wants. Because a resource id may
  sit on only one topic per module, a source that serves two topics is **split into two ids**, with
  `est_minutes` divided between them so the module budget does not move.

**Totals:** 16 resources marked optional · 3 either/or groups · 18 topics that gained a source
they lacked, plus 3 resources moved to the topic they actually serve · 17 resources split into 34
(143 → 160 resources) · 54 `focus` lines. `learn check` passes.

No resource id recorded in `learn/vault/modules/*/resources.yaml` was renamed
(`a1-karpathy-build-gpt`, `p0-karpathy-deep-dive`, `p0-swyx-ai-engineer`, `p0-willison-year-in-llms`
are all untouched).

## The two named fixes, as they now read

`attention` no longer presents three flat required items, and `rope-deltas` no longer points only
at the Raschka repo:

```yaml
      - id: attention
        resources: [a1-karpathy-build-gpt, a1-cs336-assignment-1, a1-raschka-book-ch2-5]
      - id: rope-deltas
        resources: [a1-raschka-repo, a1-cs336-lectures-3-4]
...
      - id: a1-cs336-lectures-3-4
        title: "Stanford CS336 lectures 3-4: architectures and attention variants"
        est_minutes: 360
        focus: "Lectures 3 and 4: RoPE, RMSNorm, SwiGLU and pre-norm"
      - id: a1-cs336-assignment-1
        title: "CS336 Assignment 1 (Basics): transformer, BPE, AdamW, training loop from primitives"
        lane: CS336
      - id: a1-raschka-book-ch2-5
        title: "Raschka, Build a Large Language Model (From Scratch), chapters 2-5"
        alternative_of: a1-cs336-assignment-1
        lane: Raschka
```

**Deviation from the brief, deliberate.** The brief asked for `a1-raschka-book-ch2-5` to become
`alternative_of: a1-cs336-lectures-1-4`. The syllabus does not support that: README phase 1 reads
"Karpathy (3 videos) → CS336 L1–4 → **Raschka ch 2–5 or CS336 A1** → scaling → nanochat", and
research/05 module 1 step 5 reads "CS336 Assignment 1 (Basics) … **OR** Raschka Ch. 2–5 … Do not do
both", with the lectures in *both* lanes (the lean lane still says "CS336 L1–4 for architecture
deltas"). Pointing Raschka at the lectures would encode a rule that lets the learner skip the
lectures, which no source says. So the group is Raschka ch 2–5 ↔ CS336 Assignment 1 — exactly what
the `pick-one-lane` chore has always said — and Assignment 1 moved from `gpt2-repro` to `attention`
so both members of the group sit on one topic (the app refuses the same resource id on two topics,
and a group split across topics cannot be enforced). `gpt2-repro` keeps nanochat, which is the
actual GPT-2-class reproduction in the README.

## Where the syllabus was ambiguous, and the call made

1. **Raschka's lane partner.** The brief said to point Raschka at the CS336 *lectures*; README and
   research/05 both say the choice is Raschka ch 2–5 **or CS336 Assignment 1**, with the lectures in
   both lanes. Grouped Raschka with Assignment 1 and moved Assignment 1 onto `attention` so the
   group lives on one topic. Full reasoning at the top of this file.
2. **Splitting a single blog post.** A resource id may sit on only one topic in a module, so a post
   that genuinely serves two topics had to be split (Anthropic's Contextual Retrieval, Hamel's
   "Your AI Product Needs Evals", Anthropic's "Demystifying evals", the OpenAI agents guide, OWASP
   2026). Minutes were divided, never duplicated, so no module's budget moved.
3. **Braintrust.** README lists it "for the CI pattern"; research/06 grades the platform
   "OPTIONAL". Marked optional with a focus line saying to read the pattern, not adopt the tool.
   `ci-gate` therefore has no required *source* — it still has the `b6-ci-gate` check.
4. **Guardrails AI vs NeMo Guardrails.** Research lists four interchangeable implementations rather
   than an "or", so this is an optional second read, not an either/or group.
5. **llama.cpp.** Not optional in the abstract — optional *for this track*, which serves on vLLM.
   Flagged as such in the focus line rather than dropped.
6. **`multiple-comparisons` (b8) now has no required source.** Its only resource is the unofficial
   third-party Miller implementation, which research explicitly calls a reference. No cited source
   in the whole track covers multiple comparisons; this is a real gap in the syllabus, and the
   learner's own MSc statistics is the intended filler. Left visible rather than papered over.
7. **`b5-langchain-agent-evals` kept required.** Research grades *LangSmith the platform* OPTIONAL,
   but calls this specific article a "useful read", and it is the only source on `scaffold-confound`,
   which has no check. Kept required with a focus line narrowing it to the one idea.
8. **HF Evaluation Guidebook kept required.** Research says it "complements rather than replaces"
   Tier 1, which is not the same as optional, and the README names it in the B3 row. Narrowed with
   a `focus` on the "evaluating your evaluator" chapter instead.
9. **`a6-jxnl-systematically-2024` kept required.** It partly duplicates the 2025 essay, but it is
   the only source on `query-rewriting`, so it was given a focus line rather than demoted.
